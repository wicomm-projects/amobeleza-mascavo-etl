# Briefs das sessões das fases 1, 3 e 6

Cada fase roda numa sessão própria, em worktree própria, com branch a partir de `origin/develop` (depois do merge da
fase 0) e PR para `develop`. **Nenhum merge sem autorização do Matheus.** Leia antes: `CLAUDE.md`,
`docs/planos/2026-11-18-estrutura-inicial-fases-0-1-3-6.md`, `docs/adr/`, `docs/contrato/`.

## Regras comuns

- **Produção intocável.** Não há chave nem usuário de banco ainda. Não conecte em nenhum banco da cliente; o root que
  aparece nas docs da WPP nunca é usado. Destino só o Docker local (`npm run db:up`).
- Mexa só em: `src/connectors/<fonte>/`, `db/schema/<banco>/<tabelas da fase>.sql` e `docs/conectores/<fonte>.md`.
  Núcleo (`src/core/`, `src/config/`), `package.json` e lock ficam como estão; se precisar mudar, pare e pergunte.
- Todas as dependências já estão instaladas (axios, zod, mysql2, @google-analytics/data...).
- Banco: só por `src/core/db/index.ts` (o ESLint barra `mysql2`, pools e conexões cruas fora do núcleo). Lote vazio em
  `replaceAll`/`replaceDateWindow` é recusado; `allowEmpty` só quando a fonte confirmar que não há dado.
- Cliente HTTP: `createGetClient` de `src/core/http/transport.ts` (só GET, só caminho relativo "/...", sem redirect). Gravação: o `writer` que o runner entrega no
  `ctx` (estratégias em `src/core/db/writer.ts`). Validar resposta de API com zod na borda.
- Sem suíte de testes de conector agora (vêm com as chaves). Verificação: `npm run typecheck`, `npm run lint`,
  `npm run etl -- db:apply`, `npm run etl -- run <job> --brand <b> --fixture <json de exemplo público>` gravando no
  Docker local, e `npm run etl -- check-access` mostrando "aguardando chave".
- Fixtures só com exemplos públicos da documentação da API (nada de dado da cliente). Pasta:
  `src/connectors/<fonte>/fixtures/`.
- Ao terminar: PR para `develop` com o que ficou pronto, o que depende de chave e as dúvidas. Não mergear.
